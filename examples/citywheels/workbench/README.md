# Real-time CityWheels workbench

From ai-audit:

```sh
npm --prefix ../evalLOL run build
npm run example:helpdesk
```

Open the full URL printed in the terminal, including its token fragment. The server binds only to `127.0.0.1`, on port 8799 by default (`HELPDESK_PORT` overrides it). `INTENTGAUGE_ROOT` and `CITYWHEELS_PYTHON_ROOT` select other checkouts. Keep the terminal running.

## Try the full loop

1. Keep **ai-audit + Quinelings**, **Offline**, and **refund-1002** selected. Click **Run this question**. Watch actual model and tool events appear, followed by the answer, independent evaluation and audit verification.
2. Open **Decision receipt**, **Audit records**, **Generated Quineling source**, and **Evaluation report**. These are generated by that run, not prerecorded illustrations.
3. Expand the policy editor and click **Compile Quineling**. It compiles the displayed QDL intent into a draft artifact and shows its source identity.
4. Change the `shareHalf` input value from `0.5` to `0.75`, compile again, then run the same refund case. The actual refund changes from 340 EUR to 360 EUR; the independent 340 EUR expectation stays fixed, so evaluation fails. Inspect the new receipt and policy snapshot. This is an intentional policy intervention, not a discovered production defect.
5. Click **Use default policy**. Select **Live · OpenAI (paid)** and run the case to see real model calls. The launcher loads the ignored repository `.env` if present; the browser never receives the provider key. Model calls are billable, and the all-cases button executes the selected test set: 21 business cases or 9 ambiguity/abstention cases.
6. Switch to **Original Python agent** to run its actual loop and compare its behavior. QDL drafts do not apply to that implementation. Both targets share business expectations; no audit evidence is invented for Python.

The question is editable, but the selected case's expectations remain visible and unchanged. Choose a matching case; an arbitrary rewritten question is not automatically assigned a valid oracle. The individual-question view does not test cross-case relations; the full business-set evaluation includes them.

The ambiguity set exercises missing identity, mixed requests, conflicting policies and abstention. Its phrase-based checks are development controls, not independent semantic gold. A failed safety check remains a failed evaluation even when the audit chain verifies. See the [production architecture proposal](../../../docs/helpdesk-architecture.md) for application ownership and Temporal placement.

## What remains on disk

The workbench keeps its run manifests, streaming events, policy drafts, generated artifacts, evaluation reports and decision receipts under `live/helpdesk-workbench/`. Worker inputs, copied booking/policy fixtures, observations and actual audit logs stay under `live/evaluations/`. Evaluation links connect the two. History reopens completed runs after a server restart. These directories are ignored by Git and require manual retention management.

The data set is synthetic. Questions and model outputs are retained separately from the content-free audit metadata; use this workbench for fixture experiments. A compiled draft is not a qualified production policy. Agent tool calls produce quotes. The separate execution view can change the synthetic backend only after scoped authority, customer consent and operation review; it never transfers real funds.

Stopping a request aborts its active worker. Partial evidence may remain and is not presented as a completed run. Ordinary model/API failures are retained as failed evaluation executions.

## Verification

```sh
node --test examples/citywheels/scripts/helpdesk-workbench.test.mjs
```

This drives the HTTP API with real offline worker processes: streamed model/tool events, authenticated access, QDL draft compilation, retained audit chain, replay receipt, a changed-policy regression, history reload and the Python target. It makes no paid calls. The test is skipped when the separate IntentGauge build is unavailable.
