# 46. A deterministic gate checks proposed tool calls before the client receives them
Status: Accepted (2026-10-29). Extends [0009](0009-inspect-whole-request.md); keeps [0045](0045-local-advisory-injection-judge.md) advisory.
## Context
Blocking on injection-like content is too slow or too inaccurate for the request path. On 36 synthetic cases the regex rules missed 7 of 18 attacks. The local Qwen judge took 2–11 s per tool result on an M1 and flagged 1 of 24 ordinary repository chunks. False blocks compound per session: at 4% per tool result, 50 results stop about 87% of sessions; at 1%, about 40%. Adaptive attackers defeat content classifiers. Harm starts when the agent acts. The proxy already parses the client-executed tool calls in each response (`src/extract.ts`), but delivers the response unchanged.
## Decision
- An optional `actionGate` in `gateway.json` lists tools by exact name. Each entry has `mode` (`observe` or `enforce`), sensitive `arguments` as JSON paths (`$`, `$.to`) and an `allow` list: a host, `*.domain` for its subdomains, an email address, `@domain`, a phone number or an IBAN. Unlisted tools pass unchecked. Without `actionGate` nothing changes.
- For each call to a listed tool, fixed rules take atoms from the string values under its arguments: hosts of URLs with a scheme, a whole value shaped like a hostname, and the scanner's email, phone and IBAN matches as destinations; every other scanner match is a finding. No model runs.
- Origin of an atom: `user` if it occurs in user message text; `system` if only in system, developer or instructions text; `untrusted` if only in tool results, tool definitions or assistant turns; `none` if nowhere; `unknown` when the provider holds the history (`previous_response_id`, `conversation`). Client system prompts name many hosts, so `system` does not pass.
- A destination passes if it is allowed or its origin is `user`. A finding never passes. Arguments that are not a JSON object fail. A call fails if one atom fails.
- `observe` delivers the response unchanged and records what would be held. `enforce` holds every tool call of a response that contains a failed call and ends the response as a text answer with a normal stop reason, naming the tool and `audit_action_held`. Text parts stream without delay; tool-call parts wait for the end of the response. Non-streaming responses are rewritten the same way.
- The `llm-call` record gets `actionGate.calls`: tool, call index, mode, result and, per atom, argument path, kind, origin, the source path of an untrusted occurrence, whether it was allowed and its result. Never a value or its hash ([0007](0007-log-stores-no-values.md)). The gate configuration enters `configDigest` ([0014](0014-versioned-inspection-profiles.md)). `/metrics` counts calls by mode and result.
- Injection signals and model judgments never decide the gate; they remain advisory evidence beside its results. Quinelings is not on this path; richer policies are compared offline in `lab`.
## Consequences
- The gate stops sends, uploads and payments to destinations that untrusted content supplied, and secrets placed in actions, in any language or wording, at microsecond cost and without a model.
- It does not see provider-executed tools, unlisted tools, answers changed without a tool call, or destinations the user also typed. Shell commands are covered only through URLs with a scheme, addresses and findings in them. An attacker can still use an allowed destination.
- A legitimate destination read from a tool result (an address from a CRM lookup) is held until it is allowed or the user types it. Observe mode measures this friction before enforcement.
- The proxy rewrites responses for the first time. Three streaming formats gain parsing, replacement code and tests. Clients receive tool-call arguments at once instead of streamed.
- `enforce` fails closed for listed tools; unparsable arguments hold the call.
