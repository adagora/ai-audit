# 74. Optional PII tokens live in a scoped encrypted vault
Status: Accepted (2026-11-06). Supersedes the unnumbered-placeholder requirement of [0009](0009-inspect-whole-request.md) only when the vault is enabled. Extends [0007](0007-log-stores-no-values.md), [0011](0011-response-content-per-key.md), [0014](0014-versioned-inspection-profiles.md) and [0050](0050-text-inspection-deadline-off-the-event-loop.md).

## Context
Irreversible redaction prevents a customer-facing answer from referring to the original contact details. Restoring values inside an agent loop would expose them again. A mapping store has different access and retention requirements from an audit log.

## Decision
- Opt in through `piiVault: {directory, ttlSeconds?}` and a separate 32-byte encryption key in `AUDITLINE_PII_VAULT_KEY` (legacy prefix supported). Never accept an encryption key in configuration or generate one silently. Keep zero runtime dependencies; use Node's authenticated AES-256-GCM implementation.
- Require virtual keys, redact mode, no exact-value allowlist and no auxiliary model judge. The existing detected email, phone, PESEL and IBAN spans become random 192-bit tokens; credentials retain irreversible redaction. Text traversal, nested JSON and split-part inspection remain shared with the ordinary scanner and its deadline workers. Workers generate transient mappings, hold no vault key and write nothing.
- Require an application-selected opaque UUID in `x-audit-pii-scope`, remove it before forwarding, and bind every mapping to that conversation and virtual-key hash with a keyed scope digest. Scope selection and channel/customer authentication belong to the host application; untrusted customers must not select another customer's scope.
- Persist mappings before any model/counting call. Each immutable owner-readable file contains an encrypted mapping and an authenticated version, scope, expiry, nonce and token binding. Publish through an fsynced temporary file and exclusive link; refuse collisions, symlinks, permissive storage and failed writes. Concurrent writers never replace a token. Vault failure blocks the forward. Default lifetime is 24 hours, at most 30 days. Reads enforce expiry; `vault-prune` authenticates and deletes expired mappings. A crash can leave an encrypted temporary file or unused mapping.
- Ordinary keys receive tokens. Only a key explicitly configured with `piiRestore: true` restores assistant text, and only tokens present in that request, within its scope and lifetime. Never restore tool-call arguments, reasoning, metadata or error responses. This key belongs only at a trusted customer delivery boundary; restored text must not enter model history without passing inspection again.
- Customer delivery buffers a bounded response (request size limit, default 32 MiB) under the request deadline, judges actions before restoration, and restores JSON or SSE text across token fragments in the three supported API formats. Malformed, incomplete, oversized or failed delivery returns a fixed 502 without partial content. SSE framing remains supported, but delivery waits for completion.
- Audit records retain only the tokenization version and delivery policy alongside normal findings/profile identity. Content logs mask token references; hashes and usage describe the pre-restoration model response. No original values, scope header or encryption key enter logs. Old irreversible mode is unchanged.
- Fail closed on binary/remote attachments, audio/video, provider-held history and provider-executed tools in vault mode until their tokenization path is implemented. Arbitrary encoded text, free-text names/addresses and additional channel adapters remain uncovered; this feature does not establish exhaustive PII detection.

## Consequences
The vault is a local component, not a managed secrets product. Protect its directory, backups, process memory and separately supplied key. There is no automatic key rotation, key recovery, cloud KMS integration or storage quota; changing the key makes old tokens unusable. Expiry blocks restoration but physical deletion requires scheduled pruning and a backup retention policy.

Applications can keep tokenized agent histories and deliver restored customer text through an explicit trusted boundary. Stable identities across requests require keeping the tokens; repeated raw values receive new random tokens. Universal channel coverage and a claim that no PII reaches any model require additional detection, integration and evaluation work.
