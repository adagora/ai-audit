# 49. The audit log rotates into linked segments; old segments leave only by a recorded prune
Status: Accepted (2026-10-29); segment name and pruned-anchor rule superseded by [0056](0056-segment-order-and-anchors-without-the-clock.md) (Proposed). Extends [0002](0002-hash-chained-log-with-anchors.md), [0016](0016-fail-closed-when-log-unavailable.md), [0018](0018-keyed-session-linking.md) and [0026](0026-store-each-program-once.md).
## Context
The log is one file that only grows. The proxy rebuilt its session index at start with one `readFileSync` of the whole file, and the CLI readers (`verify`, `report`, `stats`, `context`, `workbench`, `decide`, `replay`, `receipt`, `policies`) read it the same way. Node cannot hold a string above 536,870,888 characters; at about 1.7 KB per `llm-call` that is roughly 300,000 records, weeks of traffic for a team of agents. Past it, session linking stopped with only a counter, and the CLI readers crashed. AI Act Art. 19 and 26(6) ask deployers of high-risk systems to keep logs for at least six months, and data protection asks to delete them afterwards. There was no way to do either without editing the chained file, which `verify` reports as tampering.
## Decision
- Rotation closes the current file and starts a new one. While holding `<log>.lock`, it renames `audit.jsonl` to `audit.<UTC time of rotation>.jsonl` (stem, compact ISO time with milliseconds, extension) and writes the first record of a new `audit.jsonl`: `{kind: "segment", previous: {file, count, head}}`, where `head` is the last hash of the closed file. Each file chains from genesis on its own. `<log>.lock`, `<log>.session-key` and `<log>.budgets` keep their names. A torn last line is not rotated.
- `ai-audit rotate --log LOG` rotates on demand, for example daily next to `anchor`. `serve` rotates before an append when the file is larger than `--rotate-bytes`, default 256 MiB, 0 to disable. An append to a missing file next to closed segments first writes the `segment` record, so a file moved aside by hand, or a rotation cut short after its rename, continues the series. Rotation runs under the append lock; a failure is a log failure under ADR 0016.
- A log path names a series: closed segments with the same stem in the same directory, ordered by name, then the current file. `verify` and every reader take the series. `verify` checks each file's chain and each `segment` record against the file before it, and names the file of a break. An anchor matches the file that holds a record with its count and head.
- Readers stream each file line by line, so no file has to fit in one string. They read the whole series: reading only the segments of an interval is left for later, because a call is appended when it ends and can land after a rotation that followed its start. The proxy rebuilds its session index from the newest closed segment and the current file.
- An `AuditLog` that remembers which programs it stored (ADR 0026) forgets them when the current file changes, so each segment gets its own `program` record. `replay` looks for a program anywhere in the series.
- `ai-audit prune --log LOG --keep-days N` deletes the oldest closed segments whose last record is older than N days. It refuses a series that does not verify. It first appends a content-free `prune` record to the current file with each segment's name, record count, head, and first and last time, then deletes them. A missing first segment that no `prune` record lists is a break, and so is any missing segment after it. Anchors older than the first kept segment that match no kept file are counted as pruned, not failed. There is no default retention and no automatic deletion: the operator sets N; any six months fit in 184 days.
## Consequences
- No file grows much past the rotation size, and no reader needs a file to fit in one string. A six-month series at the default size is a few hundred files.
- CLI readers still hold every record of the series in memory. A long series needs a machine with that memory, or a later change that reads only the segments of an interval.
- `verify` after a prune starts at the oldest kept segment; the `prune` records and the anchors file are the evidence for what came before. Anchors still have to be stored apart from the log.
- A deleted segment cannot be replayed. Decisions whose evidence must outlive the retention window need a portable receipt (ADR 0036) taken before the prune. A decision whose program record landed in the segment before a rotation loses its program when that segment is pruned.
- Rotation renames a file that backup tools, `tail -f` and log shippers may hold open; they must follow the name, not the inode.
- Each segment stores again the programs it uses. A session that spans a restart and two rotations splits into two.
- The TLA+ model of the chain (`spec/AuditChain.tla`) does not model rotation yet.
